## Product Requirement

After Google Sign-In, new users must connect Gmail before investigation can begin. This page explains what access is being requested, why it's needed, and provides a single clear CTA to authorize. Trust and transparency are core product values.

## Current State

`src/pages/onboarding/ConnectGmailPage.tsx` is a placeholder from FE-003. No Gmail OAuth trigger exists.

## Target State

- `ConnectGmailPage` explains Gmail access and provides a CTA
- Clicking CTA redirects to backend Gmail OAuth
- After OAuth return, the page reflects connection status and advances to investigation
- `useGmailStatus()` hook available throughout the app
- Sidebar "Connected" status is wired to real data (FE-010 builds on this)

## Scope

**Create `src/hooks/useGmailStatus.ts`:**
```typescript
function useGmailStatus() {
  // GET /gmail/status
  // Returns { connected: boolean; email: string | null; lastSync: string | null }
  // TanStack Query, staleTime: 30s
}
```

**Implement `src/pages/onboarding/ConnectGmailPage.tsx`:**
- If Gmail already connected (user navigates back): redirect to `/app/dashboard`
- Header: "Connect your inbox" (translated)
- Explanation copy (2–3 sentences): what Inbox Detective reads, what it does with it
- Privacy assurance line: links to `/privacy`
- CTA: "Connect Gmail" → `GET /gmail/connect` (full page redirect via backend)
- Loading state while checking Gmail status

**Handle Gmail OAuth return:**
- Backend redirects back to `/onboarding` after Gmail OAuth
- `ConnectGmailPage` checks `useGmailStatus()` on mount
- If `connected === true` → redirect to `/onboarding/investigating` (trigger investigation)
- If `connected === false` + `?error=` query param → show error state with retry

## Agent Notes

- Like Google OAuth, the Gmail connect is a **full page redirect** — `window.location.href = VITE_API_BASE_URL + '/gmail/connect'`.
- The backend returns the user to `/onboarding` after Gmail OAuth. `ConnectGmailPage` must check Gmail status on every mount to detect the post-OAuth state.
- Do NOT cache Gmail status with a long staleTime during onboarding — use 0 or `refetchOnMount: true` to always get fresh status.
- The explanation copy must be honest and specific — do NOT write vague "we use AI to analyze your emails." Explain what is accessed (subject, sender, body) and why (to find discoveries).
