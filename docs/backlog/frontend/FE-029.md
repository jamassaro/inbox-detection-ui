# FE-029 — Accessibility P0 Fixes

**Epic:** ACCESSIBILITY  
**Priority:** P1  
**Status:** NOT_STARTED  
**Parallel-safe:** NO — depends on most UI tickets being substantially complete  

---

## Product Requirement

Critical user journeys must be keyboard accessible and usable by screen reader users. Several components have known accessibility gaps that will affect real users (especially in forms and modals).

## Current State

The existing prototype has no visible focus states, no ARIA attributes, and form inputs without labels. All new components built during V1 tickets should follow accessible patterns, but a final audit pass is needed.

## Scope

**P0 fixes (launch blockers):**

1. **`<html lang>` attribute** — must reflect active locale (`useLocale()` sets this in FE-002; verify it's working correctly)

2. **Visible focus states** — ensure all interactive elements have visible focus rings. Add to `src/index.css`:
   ```css
   :focus-visible { outline: 2px solid #111827; outline-offset: 2px; }
   ```
   Remove any `outline: none` rules that suppress focus.

3. **Search input label** — `DiscoveriesPage` search input has no `<label>`. Add `aria-label={t('discoveries.filters.searchLabel')}`.

4. **Filter tabs ARIA** — active filter button needs `aria-pressed="true"` (or `aria-selected` if using tablist pattern).

5. **`Modal` focus management** (FE-005) — verify:
   - Focus moves to first focusable element on open
   - ESC closes and returns focus to trigger element
   - Tab key cannot leave the modal while open

6. **`ConfirmModal` button labels** — ensure "Confirm" buttons have descriptive `aria-label` for context: `aria-label={t('settings.confirmations.disconnectGmail')}`.

7. **Toast announcements** — `ToastContext` renders toasts with `role="status"` and `aria-live="polite"` (verify in FE-005 implementation).

8. **Icon-only buttons** — Sidebar settings icon, LanguageSelector if icon-only, EmailDrawer close button — all need `aria-label`.

9. **`AgentActionPanel` Level 3 button** — the "Send email" / "Create event" confirmation buttons need clear accessible names that convey the consequential action, not just "Confirm".

10. **`ReminderModal` date input** — `<input type="date">` must have associated `<label>`.

**P1 fixes (should have):**
- `<nav>` landmark on Sidebar
- `<main>` landmark on AppLayout content area
- Skip navigation link

## Agent Notes

- Use `:focus-visible` not `:focus` — `:focus` shows ring on mouse click which is usually undesirable; `:focus-visible` only shows on keyboard navigation.
- ARIA labels must be translated. `aria-label={t('common.actions.close')}` not `aria-label="Close"`.
- Do NOT add `role` or `aria-*` attributes speculatively where semantic HTML would suffice. A `<button>` element is already a button — no `role="button"` needed.
