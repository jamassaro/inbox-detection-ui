# FE-002 — i18n Foundation

**Epic:** I18N  
**Priority:** P0  
**Status:** NOT_STARTED  
**Parallel-safe:** YES — parallel with FE-001; coordinate `apiClient.ts` Accept-Language step at end

## Product Requirement

Production V1 supports English and Spanish. i18n is a cross-cutting architecture requirement — not a feature added at the end. Every component built after this ticket must use `useTranslation()`. Building components with hardcoded strings and retrofitting later doubles the work and introduces bugs.

## Current State

No i18n library is installed. All user-facing strings are hardcoded in JSX. `package.json` has no `i18next` or `react-i18next` dependency. No locale files exist.

## Target State

- `react-i18next` configured with `en` (default) and `es` locales
- 24 locale JSON files created (12 namespaces × 2 languages) with English stubs and Spanish stubs
- `useLocale()` hook exposes `locale` and `changeLocale()`, persists to localStorage, updates `<html lang>`
- `src/lib/formatting.ts` provides `formatDate`, `formatRelativeDate`, `formatCurrency`, `formatNumber`, `formatMeetingTime`
- `LanguageSelector` component renders an EN|ES toggle
- All 5 existing prototype components converted to use `useTranslation()`
- `apiClient.ts` reads locale from `useLocale` / localStorage for `Accept-Language` (coordinate with FE-001 agent)

## Scope

**Install:**
- `i18next`, `react-i18next`, `i18next-browser-languagedetector`

**Create `src/i18n/index.ts`:**
- Init i18next with `i18next-browser-languagedetector`
- Detection order: `localStorage` key `inbox-detective-locale` → `navigator.language` → fallback `en`
- `load: 'languageOnly'` (maps `es-MX`, `es-CL`, etc. → `es`)
- Namespaces: `common`, `public`, `onboarding`, `investigation`, `discoveries`, `subscriptions`, `detective`, `calendar`, `reminders`, `billing`, `settings`, `errors`
- Default namespace: `common`

**Create locale files** (stubs acceptable — full population in FE-030):

                      subscriptions,detective,calendar,reminders,billing,
                      settings,errors}.json

Each file needs at minimum the keys used by the 5 existing converted components (see Likely Files).

**Create `src/contexts/LocaleContext.tsx`** + **`src/hooks/useLocale.ts`:**
- `changeLocale(locale: 'en' | 'es')` calls `i18n.changeLanguage`, persists to localStorage, sets `document.documentElement.lang`
- Exported as `useLocale()`

**Create `src/lib/formatting.ts`:**
```typescript

```

**Update `src/main.tsx`:**

## Agent Notes

- Do NOT use English text as translation keys. Use semantic keys: `common.nav.offers`, not `"Offers"`.
- `load: 'languageOnly'` in i18next config is essential — without it, `es-MX` users get English fallback.
- `formatCurrency` must accept a `currency` code as a separate argument. Currency is NOT derived from locale. A Spanish-speaking user in New York still uses USD.
- `Intl.RelativeTimeFormat` requires choosing the right unit (days, hours, minutes) — implement threshold logic.
- Do NOT import `i18n` directly in components. Always use `useTranslation()` hook.
- The `LanguageSelector` must NOT cause a re-render of the entire tree on language change — i18next handles this correctly via its React integration.
- `noUnusedLocals: true` in tsconfig — remove any unused locale variables after conversion.
