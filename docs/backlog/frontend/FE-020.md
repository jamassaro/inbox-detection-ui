# FE-020 — Reminder Flow

**Epic:** REMINDERS  
**Priority:** P0  
**Status:** NOT_STARTED  
**Parallel-safe:** NO — depends on FE-004, FE-005, FE-019  

---

## Product Requirement

Discoveries with deadlines (expirations, renewals, meeting requests) should offer "Remind me." Free users hit a Pro paywall. Pro users select a time option, the reminder is created, and they see confirmation. The reminder flow must survive the upgrade flow — if a Free user upgrades because they clicked "Remind me," they should land back at the same discovery with the reminder dialog open.

## Current State

No reminder flow exists. This is entirely new.

## Target State

- `ReminderModal` opens from any Discovery action `remind`
- Free users see `UpgradePrompt` inline in the modal
- Pro users see reminder options and create/edit/cancel reminders
- After payment, reminder dialog auto-resumes (via upgrade context)
- Translated in EN and ES

```typescript
}
function useCreateReminder() {
  // POST /reminders { discoveryId, remindAt: ISO8601 }
  // Mutation
}
function useDeleteReminder() {
  // DELETE /reminders/:id
  // Mutation
}
```

**Create `src/components/ReminderModal.tsx`:**
```tsx
interface ReminderModalProps {
  discoveryId: string;
  discoveryDate?: string;  // ISO — used to compute relative options
  isOpen: boolean;
  onClose: () => void;
}
```

If Free user:
- `<RequiresPro feature="reminders">` renders upgrade prompt inline within the modal
- [Unlock with Pro] calls `useUpgradeRedirect` with `{ source: 'reminder', returnPath, discoveryId, pendingAction: 'remind' }`

If Pro user:
- Reminder options (translated):
  - Tomorrow
  - 1 day before [discoveryDate] (conditional, only if `discoveryDate` exists)
  - 3 days before
  - 7 days before
  - Custom date (date input)
- If existing reminder: show "Reminder set: [date] ✓" with Edit / Cancel options
- [Set reminder] button → `useCreateReminder` mutation
  - Loading state on button
  - On success: close modal + `useToast().success(t('reminders.confirmation.set', { date }))`
  - On error: show error inline in modal
- Cancel reminder: `ConfirmModal` → `useDeleteReminder` → toast

**Handle post-upgrade reminder resumption:**
In `UpgradeSuccessPage.tsx` (FE-017), after entitlement refresh:
- Check `upgradeContext.pendingAction === 'remind'` and `discoveryId` present
- Navigate to `returnPath` (discovery detail) with `?openReminder=true`

In `DiscoveryDetailPage.tsx` (FE-014):
- On mount, check `?openReminder=true`
- If present: auto-open `ReminderModal`
- Clear the query param from URL

## Agent Notes

- Reminder options "1 day before", "3 days before", "7 days before" are computed from `discoveryDate` — they result in absolute ISO 8601 timestamps sent to the backend. The frontend computes the timestamp; the backend stores it.
- Custom date input: use a native `<input type="date">` for V1. Do not add a date-picker library.
- `ReminderModal` uses `Modal` base component from FE-005 for focus management.
- Translated success toast must use interpolation: `t('reminders.confirmation.set', { date: formatDate(remindAt, locale) })`.
