## Product Requirement

The application has no authentication. All routes are currently public. Production V1 requires Google Sign-In, protected routes under `/app`, a callback handler for the OAuth redirect, and session state available throughout the app.

## Current State

`src/App.tsx` renders a flat `<BrowserRouter>` with 6 routes, all public, no auth check. There is no `AuthContext`, no session check, no protected route wrapper. The Sidebar and all pages render unconditionally.

## Target State

- `AuthContext` provides `user`, `isAuthenticated`, `isLoading`, `logout()` to the entire app
- `<ProtectedRoute>` redirects unauthenticated users to `/`
- Router restructured: public routes at root level, authenticated routes under `/app/*`
- `AuthCallbackPage` handles the Google OAuth code exchange
- All route slots for future pages are pre-defined (with placeholder components) to prevent subsequent tickets from needing to modify `src/App.tsx`
- 401 responses from `apiClient` trigger session expiration → redirect to `/`

## Scope

**Create `src/contexts/AuthContext.tsx`:**
```typescript
interface AuthState {
  user: User | null;
  isAuthenticated: boolean;
  isLoading: boolean;
  logout: () => Promise<void>;
}
```
- On mount: `GET /auth/me` via `apiFetch` — sets `user` or sets `isAuthenticated: false`
- Listens for `auth:expired` window event (dispatched by `apiClient` on 401) — clears user, redirects to `/`
- `logout()` calls `POST /auth/logout`, clears state, redirects to `/`

**Create `src/components/ProtectedRoute.tsx`:**
- If `isLoading`: render `<LoadingSpinner />` (use inline spinner until FE-005 creates the shared one)
- If `!isAuthenticated`: `<Navigate to="/" replace />`
- Otherwise: `<Outlet />`

**Restructure `src/App.tsx`:**
```
/                          → LandingPage (lazy)
/auth/callback             → AuthCallbackPage (lazy)
/onboarding                → ConnectGmailPage (lazy) [protected]
/onboarding/investigating  → InvestigationProgressPage (lazy) [protected]
/onboarding/results        → InvestigationResultsPage (lazy) [protected]
/upgrade                   → UpgradePage (lazy) [public — accessible pre-auth for pricing]
/upgrade/success           → UpgradeSuccessPage (lazy) [protected]
/privacy                   → PrivacyPolicyPage (lazy) [public]
/terms                     → TermsPage (lazy) [public]
/app                       → AppLayout (lazy) [protected via ProtectedRoute]
  /app/dashboard           → DashboardPage (lazy)
  /app/discoveries         → DiscoveriesPage (lazy)
  /app/discoveries/:id     → DiscoveryDetailPage (lazy)
  /app/subscriptions       → SubscriptionsPage (lazy)
  /app/chat                → ChatPage (lazy)
  /app/settings            → SettingsPage (lazy)
  /app/settings/billing    → BillingPage (lazy)
```
All lazy-imported pages use `React.lazy()` + `<Suspense>` with a fallback spinner. Create minimal placeholder components for pages not yet implemented (returns `null` or a loading div) — this prevents build failures and avoids future `src/App.tsx` merge conflicts.

**Create `src/pages/AuthCallbackPage.tsx`:**
- Reads `?code=` from URL search params
- This page is a redirect target — the actual code exchange happens backend-side (the backend sets an httpOnly session cookie). The page simply calls `GET /auth/me` via the existing `queryClient`, on success redirects to `/onboarding` or `/app/dashboard` based on whether Gmail is already connected.
- On failure: redirect to `/` with error query param

**Create `src/components/AppLayout.tsx`:**
- Contains `<Sidebar />` + `<Outlet />`
- Replaces the current inline layout in `src/App.tsx`

**Update `src/main.tsx`:**
- Wrap app with `<AuthProvider>`

## Agent Notes

- All page imports in `App.tsx` must use `React.lazy()`. This is critical for bundle splitting and for allowing parallel development — each page ticket implements its own component without needing to touch `App.tsx`.
- Placeholder components must be valid React components that return something renderable (not `null` — use `<div />` to prevent Suspense issues).
- The `User` type must be added to `src/types/index.ts`: `{ id: string; name: string; email: string; googleId: string }`.
- Do NOT check `localStorage` for auth tokens. Session state comes from `GET /auth/me` (httpOnly cookie). The frontend never touches auth tokens directly.
- The `auth:expired` event listener in `AuthContext` must be removed on unmount (cleanup in `useEffect`).
- `AppLayout` owns the Sidebar — do not duplicate the sidebar import.
