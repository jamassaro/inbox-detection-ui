## Product Requirement

Free users encounter paywalls throughout the app (locked discoveries, reminder gate, calendar gate, chat limit). The upgrade flow must be contextual — it must remember where the user came from and what they were trying to do, so after payment they return to exactly that context and complete the interrupted action.

## Current State

No billing infrastructure exists. `src/pages/UpgradePage.tsx` is a placeholder from FE-003.

## Target State

- `UpgradePage` renders contextual upgrade copy with plan options
- Upgrade context (source, return path, discovery ID, action) is preserved in `sessionStorage`
- `useUpgradeContext` hook reads/writes upgrade context
- All paywall triggers across the app route through this system
- Translated in EN and ES

## Scope

**Create `src/lib/upgradeContext.ts`:**
```typescript
interface UpgradeContext {
  source: string;        // e.g. 'locked_discovery', 'reminder', 'calendar', 'chat_limit'
  returnPath: string;    // e.g. '/app/discoveries/abc123'
  discoveryId?: string;
  pendingAction?: DiscoveryAction;
}
function saveUpgradeContext(ctx: UpgradeContext): void  // sessionStorage
function readUpgradeContext(): UpgradeContext | null
function clearUpgradeContext(): void
```

**Create `src/hooks/useUpgradeRedirect.ts`:**
```typescript
function useUpgradeRedirect() {
  // Saves context and navigates to /upgrade?from={source}
  function redirectToUpgrade(ctx: UpgradeContext): void
}
```

**Implement `src/pages/UpgradePage.tsx`:**
- Reads `?from=` query param to show contextual message:
  - `locked_discovery` → "Your Detective found more things worth your attention."
  - `reminder` → "Set reminders so you never miss a deadline."
  - `calendar` → "Unlock Calendar actions."
  - `chat_limit` → "Get unlimited Detective access."
  - Default → "Upgrade to Inbox Detective Pro"
- Plan cards:
  - Free: current plan indicator (if already free)
  - Pro Monthly: $5.99/month — [Upgrade Now]
  - Pro Annual: $49/year — [Upgrade Now] (save badge)
- "Already Pro?" link → `/app/settings/billing`
- Clicking "Upgrade Now" → continues in FE-017

**Update `src/components/UpgradePrompt.tsx`** (created in FE-004):
- Wire to `useUpgradeRedirect` instead of plain `navigate('/upgrade')`
- Passes `{ source: feature, returnPath: location.pathname, ... }`

**Update `src/components/LockedDiscoveryCard.tsx`** (created in FE-012):
- `onUpgrade` uses `useUpgradeRedirect` with discovery context

## Agent Notes

- `sessionStorage` is used (not localStorage) — upgrade context must not persist across browser sessions.
- Pricing values in `UpgradePage` are presentational only. Never derive entitlement logic from frontend pricing constants. Stripe is the source of truth.
- The annual plan requires a separate Stripe Price ID from the monthly plan. Backend must provide both `monthlyPriceId` and `annualPriceId` in the checkout session endpoint. Do NOT hardcode price IDs in the frontend.
- The `from` query param is a UI display hint only — it does not affect backend behavior.
