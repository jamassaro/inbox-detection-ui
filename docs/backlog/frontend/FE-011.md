# FE-011 — Discovery Type System

**Epic:** DISCOVERIES  
**Priority:** P0  
**Status:** DONE — on `main` via #4 (verified 2026-09-17)  
**Parallel-safe:** YES — pure TypeScript types + mapping utility, no UI, no dependencies  

---

## Product Requirement

A Discovery is the primary domain object in Inbox Detective. The current `Offer` type is inadequate for V1 — it doesn't model subscriptions, price changes, credits, expirations, or meeting requests. Backend enum values must map through translation keys before reaching the UI.

## Current State

`src/types/index.ts` contains a minimal `Offer` interface and `FilterType` type. `src/data/mockOffers.ts` uses this type with mock data.

## Target State

- `Discovery` union type replaces `Offer` as the primary domain object
- All backend enum values (discovery type, action type, status) have corresponding translation key mappings
- A `getDiscoveryTranslationKey(type)` utility returns the correct `discoveries.types.*` key
- `Offer` type retained for backward compatibility with mock data (removed when mock data is removed)

## Scope

**Update `src/types/index.ts`** — add:

```typescript
type DiscoveryType =
  | 'subscription' | 'renewal' | 'trial_expiration'
  | 'price_change' | 'bill_change'
  | 'credit' | 'refund' | 'reward' | 'expiration' | 'cashback'
  | 'meeting' | 'action_required';

type DiscoveryStatus = 'new' | 'viewed' | 'acted' | 'dismissed';

type DiscoveryImportance = 'high' | 'medium' | 'low';

type DiscoveryAction =
  | 'remind' | 'dismiss' | 'view_source' | 'open_provider'
  | 'review_subscription' | 'investigate' | 'find_time'
  | 'track_refund' | 'ask_detective';

interface Discovery {
  id: string;
  type: DiscoveryType;
  title: string;           // AI-generated — do NOT translate
  summary: string;         // AI-generated — do NOT translate
  company: string;
  companyInitials: string; // derived from company name
  amount?: number;
  currency?: string;       // ISO currency code e.g. 'USD'
  frequency?: 'monthly' | 'annual' | 'weekly' | 'one_time';
  date?: string;           // ISO 8601
  previousAmount?: number;
  importance: DiscoveryImportance;
  status: DiscoveryStatus;
  locked: boolean;
  availableActions: DiscoveryAction[];
  confidence?: number;
}

interface DiscoveryListResponse {
  items: Discovery[];
  lockedCount: number;
  total: number;
}

interface DiscoverySourceEvidence {
  id: string;
  subject: string;
  sender: string;
  date: string;
  excerpt: string;
  gmailUrl: string;
}
```

## Agent Notes

- `title` and `summary` on a Discovery are **AI-generated text** — they come from the backend already in the user's locale. Do NOT pass them through the translation system. Render them directly.
- `company` is a proper noun — do not translate.
- `amount` and `currency` are structured — always format with `formatCurrency(amount, currency, locale)`, never with a hardcoded `$` prefix.
- The `locked` field is a boolean from the backend. Free users receive `locked: true` on Discoveries beyond their visible limit. The frontend uses this to render `LockedDiscoveryCard` — it does NOT calculate whether a Discovery should be locked.
- `companyInitials` should be derived from `company` (first letter(s)) if not provided by backend — add a helper: `getInitials(company: string): string`.
