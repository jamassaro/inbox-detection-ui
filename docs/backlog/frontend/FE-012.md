## Product Requirement

Discovery cards are the primary visual representation of the product's value. They must communicate: what happened, why it matters, the amount/date, and available actions — all while adapting to the 12 Discovery types without a separate component per type.

## Current State

`src/components/FeaturedOfferCard.tsx` — 55 lines, renders a single "Offer" type with a discount badge. `src/components/OfferListItem.tsx` — 28 lines, renders an offer as a list row. These are the starting point. `src/components/StatCard.tsx` — reusable as-is.

## Target State

- `DiscoveryCard` — extends `FeaturedOfferCard`, accepts `Discovery` type, renders type-appropriate icon/color/actions
- `DiscoveryListItem` — extends `OfferListItem`, renders Discovery as a list row
- `LockedDiscoveryCard` — renders a locked Discovery with category hint and upgrade CTA
- `StatCard` — unchanged, reused

## Agent Notes

- ONE `DiscoveryCard` component handles all 12 types via conditional rendering. Do NOT create `SubscriptionCard.tsx`, `PriceChangeCard.tsx`, etc.
- The `title` field is AI-generated text — render it as-is inside the card. Do NOT pass it through `t()`.
- `onAction` is a callback, not an internal handler. Cards display actions; pages handle them. This keeps cards testable in isolation.
- Preserve the visual design language from `FeaturedOfferCard`: white background, `rounded-xl`, `border border-gray-200`, gray-900 primary button, green badge for positive amounts.
- For the price change row: use `formatCurrency` for both amounts and a color-coded diff (red for increase, green for savings).
- `LockedDiscoveryCard` should visually suggest there's hidden content (blurred/grayed placeholder content is acceptable).
