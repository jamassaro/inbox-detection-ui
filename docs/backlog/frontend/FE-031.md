# FE-031 — Core Unit Test Suite

**Epic:** TESTING  
**Priority:** P1  
**Status:** NOT_STARTED  
**Parallel-safe:** NO — requires component tickets to be substantially complete  

---

## Product Requirement

Autonomous multi-agent development without tests is fragile. Core components and hooks need test coverage to prevent regressions as agents work in parallel. The minimum required coverage is for the components and logic most likely to break: auth, entitlements, Discovery rendering, billing flows, and i18n.

## Current State

No tests exist. Vitest is installed in FE-001. No `*.test.ts` or `*.test.tsx` files exist (except those created inline in individual tickets).

## Target State

Unit test coverage for all critical components and hooks. Tests run on `npm test` with no failures.

## Agent Notes

- Mock `apiFetch` globally in test setup — do NOT make real network calls in unit tests.
- Use `@testing-library/user-event` for user interactions (click, type) in component tests.
- Mock `i18next` translations with a simple passthrough: `t(key) => key` for most unit tests. Test actual translation output only in formatting and locale tests.
- Mock `useEntitlements` using `vi.mock` to control Free/Pro state in component tests.
