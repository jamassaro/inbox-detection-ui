## Product Requirement

The Discoveries page is the primary content view of the authenticated app. It shows all discoveries returned by the backend, filtering by type and status. Free users see their limited discoveries plus a locked count section that drives upgrade.

## Current State

`src/pages/OffersPage.tsx` is the closest existing implementation — it renders mock Offers with filters and search. `src/pages/discoveries/DiscoveriesPage.tsx` is a placeholder from FE-003.

## Target State

- `DiscoveriesPage` fetches real Discoveries from `GET /discoveries`
- Filters work (All, Ending Soon, New, Saved)
- Search is wired to API
- Locked section visible for Free users
- Loading, empty, and error states all handled
- All copy translated in EN and ES

## Scope

**Create `src/hooks/useDiscoveries.ts`:**
```typescript
function useDiscoveries(filters: DiscoveryFilters) {
  // GET /discoveries?type=&status=&search=&page=&limit=
  // Returns DiscoveryListResponse
  // TanStack Query, invalidated on dismiss/feedback mutations
}
```

**Implement `src/pages/discoveries/DiscoveriesPage.tsx`:**
- Stats row: `StatCard` × 3 (total, ending soon, new this week) — from `DiscoveryListResponse` metadata
- Filter tabs: All / Ending Soon / New / Saved — from `discoveries.filters.*` translation keys
- Search input (wired: 300ms debounce, updates query params)
- Featured section ("Don't miss these"): `DiscoveryCard` grid (featured/high-importance discoveries)
- All Discoveries list: `DiscoveryListItem` per item
- Locked section (Free users): `LockedDiscoveryCard` with count
- On `DiscoveryListItem` click: navigate to `/app/discoveries/:id`
- On `DiscoveryCard` action click:
  - `dismiss` → optimistic update, `PATCH /discoveries/:id { status: 'dismissed' }`
  - `remind` → open `ReminderModal` (FE-020) via `RequiresPro`
  - `view_source` → open `EmailDrawer` (FE-014)
  - `find_time` → navigate to discovery detail (FE-014)
  - Other actions → navigate to discovery detail
- `EmptyState` when no discoveries
- `ErrorState` with retry on fetch failure
- `SkeletonCard` × 4 while loading

**Remove or redirect `src/pages/OffersPage.tsx`:**
- The old OffersPage is superseded. Remove it or redirect `/offers` → `/app/discoveries`.

## Agent Notes

- The old `OffersPage` filter logic (client-side on mock data) must be replaced with server-side filter params. Do NOT filter client-side.
- Optimistic dismiss: use `queryClient.setQueryData` to remove the item immediately, then revert with `queryClient.invalidateQueries` on mutation error.
- The featured section shows high-importance discoveries. Derive this from `discovery.importance === 'high'` from the API response, not a separate endpoint.
- `StatCard` is reused unchanged from the existing implementation.
- Discovery feedback (`POST /discoveries/:id/feedback`) can be added to the DiscoveryCard as a lightweight "Useful / Not useful" interaction in this ticket or deferred to a follow-up.
