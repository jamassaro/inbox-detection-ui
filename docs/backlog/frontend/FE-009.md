# FE-009 — Investigation Flow

**Epic:** ONBOARDING  
**Priority:** P0  
**Status:** IN_PROGRESS (audit 2026-09-17: implementation underway; rebase onto FE-012 main needed)

## Product Requirement

The investigation is the most important product moment. After Gmail is connected, the user watches Inbox Detective analyze their inbox. This screen must make the experience feel real, honest, and impressive — not like a spinner. Real progress numbers (emails reviewed, subscriptions found, etc.) must display as they arrive.

After investigation completes, the user sees their first real discoveries. Free users see 3–5 discoveries and a locked count that drives upgrade.

## Current State

Both `InvestigationProgressPage.tsx` and `InvestigationResultsPage.tsx` are placeholders from FE-003. No polling logic exists.

## Target State

- `InvestigationProgressPage` polls `GET /investigations/:id` and displays live stats
- All 7 required states are handled: `not_started`, `starting`, `running`, `complete`, `failed`, `partial`, `retry`
- `InvestigationResultsPage` shows summary + first discoveries (connects to FE-012 DiscoveryCard)
- Investigation is triggered automatically on arrival at `/onboarding/investigating`

**Implement `src/pages/onboarding/InvestigationProgressPage.tsx`:**
- On mount: call `useTriggerInvestigation()` if no active investigation
- Poll via `useInvestigation(id)`
- Display (as they update):
  - "Investigating your inbox..." header
  - Emails reviewed count (animated number)
  - Categories found (subscriptions, price changes, credits, meetings, expirations)
  - Current status label from translation key
- On `complete`: navigate to `/onboarding/results`
- On `failed`: show `ErrorState` with retry option
- On `partial`: show partial message + continue to results
- Never leave the user on an infinite spinner — include a timeout message after 5 minutes

**Implement `src/pages/onboarding/InvestigationResultsPage.tsx`:**
- Fetches `GET /discoveries` with `entitlement-filtered` response
- Shows summary: emails analyzed count, discoveries found, potential value
- Shows 3–5 `DiscoveryCard` components (from FE-012 — coordinate dependency)
- Shows `LockedDiscoveryCard` count if locked discoveries exist (from FE-012)
- CTA: "See all discoveries" → `/app/discoveries`
- Secondary CTA (if locked): "Unlock with Pro" → `/upgrade?from=investigation_results`

## Agent Notes

- Polling must use TanStack Query's `refetchInterval` option, set to `false` when status is terminal.
- Do NOT fake progress. If the backend only provides coarse status, show what's real. Fabricated progress is a trust violation.
- The investigation ID must be stored after the POST (in component state or URL param `?investigationId=`) so the polling hook can use it.
- `InvestigationResultsPage` is a discovery-rendering page. If FE-012 is not yet complete, use a simple placeholder card. Do not block this ticket on FE-012.
- Numbers must use `formatNumber(count, locale)` — not raw template literals.
