# FE-017 — Stripe Checkout + Upgrade Success

**Epic:** PAYMENTS  
**Priority:** P0  
**Status:** NOT_STARTED  
**Parallel-safe:** NO — depends on FE-004, FE-016  

---

## Product Requirement

Clicking "Upgrade Now" must send the user to Stripe Checkout, accept payment, and return them to the exact context that prompted the upgrade — whether that was a locked discovery, a reminder, or a chat limit. A generic success page that ignores context kills conversion.

## Current State

`src/pages/UpgradeSuccessPage.tsx` is a placeholder from FE-003. No Stripe integration exists.

## Target State

- Clicking "Upgrade Now" on `UpgradePage` creates a Stripe Checkout session and redirects
- After payment, `UpgradeSuccessPage` polls entitlements until Pro is confirmed
- On Pro confirmed, restores the saved upgrade context and navigates to the original action
- All states handled: loading, success, timeout, error

## Scope

**Create `src/hooks/useCheckout.ts`:**
```typescript
function useCheckout() {
  // POST /billing/checkout-session { priceId, returnPath: window.origin + '/upgrade/success' }
  // Returns { url: string }
  // On success: window.location.href = url (full page redirect to Stripe)
  // Shows loading state while session is being created
  // On error: toast + allow retry
}
```

**Update `src/pages/UpgradePage.tsx`** (from FE-016):
- "Upgrade Now" button calls `useCheckout()` with selected `priceId`
- Button shows loading spinner while checkout session is being created
- On checkout session error: toast "Checkout unavailable. Try again." + button re-enables

**Implement `src/pages/UpgradeSuccessPage.tsx`:**
- Shows: "Activating your Pro access..." with `LoadingSpinner`
- Polls `GET /user/entitlements` every 2s until `plan === 'pro'` (max 12 attempts = 24s)
- On `plan === 'pro'`:
  1. Call `entitlementContext.refresh()`
  2. Read `readUpgradeContext()` from sessionStorage
  3. `clearUpgradeContext()`
  4. Navigate to `upgradeContext.returnPath` (default: `/app/discoveries`)
  5. Show success toast: "Welcome to Pro!" (dismissed after navigation)
- On timeout (12 attempts): show "Still activating... [Refresh manually]" + manual refresh button
- On error: show `ErrorState` with retry

**Handle Stripe return for cancelled checkout:**
- Stripe sends user to `returnPath` with `?cancelled=true` if they back out
- If landing on `UpgradePage` with `?cancelled=true`: show "No charge was made" info message
- Do NOT clear the upgrade context on cancellation — let the user retry

## Agent Notes

- Stripe Checkout is a **full page redirect** — `window.location.href = checkoutUrl`. Do NOT open in an iframe or new tab.
- The `priceId` for the selected plan (monthly or annual) comes from the `POST /billing/checkout-session` request body. The frontend sends which plan was selected; the backend resolves the Stripe Price ID. Do NOT hardcode Stripe Price IDs in the frontend.
- `UpgradeSuccessPage` polling must stop when the component unmounts (cancel the interval in `useEffect` cleanup).
- After navigating away from `UpgradeSuccessPage`, the success toast should still be visible briefly. Use `useToast().success()` before navigation, not after.
- The cancelled checkout flow: Stripe sends `{returnUrl}?cancelled=true`. The frontend detects this on `UpgradePage` (not `UpgradeSuccessPage`).
