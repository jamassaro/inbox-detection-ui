# FE-004 — Entitlement Infrastructure

**Epic:** AUTH  
**Priority:** P0  
**Status:** NOT_STARTED  
**Parallel-safe:** NO — depends on FE-001, FE-003  

---

## Product Requirement

Free and Pro users see different UI throughout the entire app. Entitlement checks must be centralized — scattering `if (plan === 'free')` throughout components makes the codebase unmaintainable and makes Pro features trivially bypassable. All paywall gates must go through one `useEntitlements()` hook.

## Current State

No entitlement system exists. The app has no concept of plans, feature flags, or paywalls.

## Target State

- `EntitlementContext` fetches `GET /user/entitlements` after auth
- `useEntitlements()` hook is the only place in the codebase that checks plan/features
- `<RequiresPro feature="...">` renders children for Pro users, renders `<UpgradePrompt>` for Free users
- Entitlements are refreshed after successful payment (consumed by FE-017)

## Scope

**Create `src/contexts/EntitlementContext.tsx`:**
```typescript
interface Entitlements {
  plan: 'free' | 'pro';
  visibleDiscoveries: number;
  continuousMonitoring: boolean;
  reminders: boolean;
  calendarActions: boolean;
  emailActions: boolean;
  dailyBriefing: boolean;
  chatQuestionsRemaining: number | null; // null = unlimited
}
interface EntitlementState {
  entitlements: Entitlements | null;
  isLoading: boolean;
  refresh: () => Promise<void>;
}
```
- Fetches `GET /user/entitlements` on mount (only when authenticated)
- Exposes `refresh()` — called by `UpgradeSuccessPage` after Stripe return
- Persists in TanStack Query cache with key `['entitlements']`

**Create `src/hooks/useEntitlements.ts`:**
- Consumes `EntitlementContext`
- Convenience booleans: `isPro`, `isFree`, `canUseReminders`, `canUseCalendar`, etc.

**Create `src/components/RequiresPro.tsx`:**
```tsx
interface RequiresProProps {
  feature: keyof Entitlements;
  children: ReactNode;
  fallback?: ReactNode; // defaults to <UpgradePrompt feature={feature} />
}
```
- Renders `children` when `entitlements[feature] === true` (or `plan === 'pro'`)
- Renders `fallback` (or default `<UpgradePrompt>`) for Free users

**Create `src/components/UpgradePrompt.tsx`:**
- Inline upgrade prompt: `"{feature description} requires Pro. [Unlock with Pro]"`
- `[Unlock with Pro]` navigates to `/upgrade?from={feature}&returnPath={currentPath}`
- Translated in EN and ES

**Update `src/main.tsx`:**
- Wrap app with `<EntitlementProvider>` (inside `AuthProvider`)

## Agent Notes

- `EntitlementContext` must only fetch when `isAuthenticated === true` (check AuthContext). If unauthenticated, skip the fetch entirely — do not trigger a 401.
- Never read `plan` directly from a component. Only use `useEntitlements()`.
- `RequiresPro` is a render-level gate only — it is NOT a security control. Backend enforces actual entitlements.
- The `feature` prop on `RequiresPro` should be a key of the `Entitlements` interface for type safety.
- `refresh()` must update the TanStack Query cache (`queryClient.invalidateQueries(['entitlements'])`) so all components using the cache reflect the new state.
